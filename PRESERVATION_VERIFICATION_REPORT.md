## 8. Deferred work (unchanged, and now correctly sequenced)

Per the standing rule — *preserve first, verify second, fix third, merge last* — none of
the following has been started:

1. **Decision E startup race** (`database.py:1555-1563`): check-then-`ALTER` with a bare
   `except Exception → RuntimeError`. Bot and dashboard both run `init_db()`, so on a
   first deploy the loser of a concurrent `ALTER` hits `duplicate column name: entry_key`
   and aborts startup — exactly when the migration is needed. Fix: tolerate
   `duplicate column name` as success.
2. **The startup change is harmful and should be cancelled, not fixed.** `main.py:337`
   puts `bot.start()` in the same `except Exception` (line 355) that was changed to
   `sys.exit(1)`, and `start.sh` halts on code 1. A transient Discord/network error
   therefore kills the bot permanently while `dashboard/app.py` keeps serving — the
   container looks healthy.
3. **R2 rework** must include the `utils/level_test_reset.py:489` exclusion and a
   **systematic enumeration of every `timed_holdings` reader**, not a sample. That reader
   filters on `guild_id`/`user_id` only, with **0** occurrences of `role_retention` in the
   file, so a retention obligation is miscounted as an "other grant". My earlier
   14-claim semantic audit was wrong about this one.
4. **Design C's own test suite** — now recoverable from
   `archive/2026-10-31-design-c:repo-files/test_purchase_grant_ledger.py` (29 tests).
5. **The Drop product decision.**

**Recommended merge unit is unchanged by the loss:** the 53-commit chain plus Design C —
hash-verified and fixing real data loss. Phase 1.5 should be **redone, smaller and
corrected**, not reconstructed; reconstruction would re-introduce the three defects above.
